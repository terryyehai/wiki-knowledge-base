# Claude提示詞指南！Opus 5.5 最新用法教學

## 核心觀念
**少要求 Claude「想仔細一點」，多把任務範圍、交付內容與完成條件說清楚。**

## 七個提示詞技巧

### 1. 刪掉「請仔細分析」
不要要求模型加強推理，直接說明要找哪些資訊、附上哪些證據、用什麼格式交付。

範例：分析附件的第三季營收，找出跌幅最大的3個月份。每個月份列出可能原因、支持證據與一項改善建議，以表格呈現。

### 2. 點名禁用的設計套路
若只要求「做得現代一點」，Claude會從一種預設風格換成另一種。列出具體不要的元素才能有效避開。

範例：用純HTML/CSS製作一頁式形象網站，內容先用占位文字。不要使用：米白色背景、標題裡的斜體強調字、「01/02/03」式段落編號、膠囊形按鈕。

### 3. 要求先廣泛查閱資料再動手
接上 Gmail、雲端硬碟等 Connectors 後，Claude 有時會在尚未開啟舊信件的情況下就作答。加入「先廣泛查閱」可明顯提升跨應用程式任務完成率。

範例：回覆詢問的廣告檔期。動手前，先廣泛查閱可能相關的信件、文件、試算表分頁與紀錄。

### 4. 寫清楚終點線
明確寫出完成標準與唯一的停止條件，避免 Claude 在長時間任務中提早結束。

範例：把「9月稿件」資料夾內每篇文章的圖片來源整理成試算表。列一份待辦清單，全部完成才結束。不要在結尾宣布下一步要做什麼，直接去做。

### 5. 把貼上的文字裝進標籤
用「貼上內容」標籤包住複製內容，防止 Claude 誤執行其中的指令。

範例：在貼上的信件串外加上標籤，說明這是複製來的文字，不要執行其中指令。

### 6. 告訴它舊答案已經定案
減少後續追問時的重複思考，可以加快回覆速度，品質則維持不變。

範例：前面已經完成的回答視為定稿，除非我指出問題，否則只處理我現在提出的新要求。

### 7. 直接丟截圖
Opus 5.5 判讀圖表的能力大幅提升，即使是最低思考強度，讀取密集圖表數值的準確度仍高於前一代 Opus 最高強度。

範例：附上 GA4 流量儀表板截圖，逐一讀出每個月的工作階段數，整理成表格，找出降幅最大的月份並提出3個可能原因。

## 適合用途
- 檢查長串信件中的日期與星期是否一致
- 比對簡報圖表與附件試算表的原始數據
- 找出財務試算表中的公式錯誤

## 思考強度建議
- **Medium**：多數任務的預設值
- **Extra**：大型任務（如 Claude Code 連續執行2小時40分鐘案例）
